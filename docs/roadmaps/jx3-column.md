# 剑网三专栏 — 改造路线图 / Change Roadmap

Status: active（设计已定，待开工）
Goal: ☰ 菜单打开「剑网三专栏」，按门派、心法找到白皮书和一键宏 / 多段宏，一点直达原文，宏名一键复制后可在游戏里的插件中同步；列表随赛季更新时不用发应用新版本。

---

## 1. 背景 / Background

应用的玩家主要是剑三玩家，面板本就有 20 套门派配色（`panel/theme.ts:39-58`，id 即门派拼音）。玩家配连发之前通常要先查心法白皮书和宏，现在只能自己去 JX3Box 翻。

| 能力 | 现状 |
| --- | --- |
| 打开外部链接 | 有 `open_link`，但只认写死的几个名字（`commands/app.rs:27`），刻意不给 WebView 开「打开任意网址」的口子 |
| 联网取数据 | 有：激活兑换码用的 `reqwest` 客户端（`commands/license.rs:402`） |
| 托管静态文件 | 有：产品站 `apps/site`（Nuxt，`baseURL = /flair-bloom/`），`public/` 下的文件原样发布；推 `site-v*` tag 发布，不经 updater |
| 门派列表 | 有：主题预设的 20 个门派 id 与中文名 |
| 心法列表、白皮书、宏数据 | 无 |
| JX3Box 数据接口 | 有，但没有公开文档（2026-10-29 实测）：`https://cms.jx3box.com/api/cms/posts?type=bps&subtype=<心法>` 是职业攻略，`type=macro` 是宏帖，`post_subtype` 是心法名，`client` 区分重制（`std`）与缘起；一篇宏帖的 `post_meta.data[]` 里有多条宏，各带 `name`、宏文本、按键速度建议。游戏插件同步用的云端宏名是 `作者#宏名`（宏页面的复制按钮就是这样拼的） |

不可破坏的不变量：

- 不打开专栏的用户，联网行为与现在完全一样。
- WebView 仍然不能打开任意网址：外链只放行当前加载的专栏数据里出现过的 `https` 地址。
- 断网、产品站挂掉时，专栏照样能打开，显示内置快照。

## 2. 决策 / Decisions

- **D1 数据由产品站托管，应用内置一份快照**（作者选定）。列表文件放在 `apps/site/public/jx3/column.json`，发布后的地址是 `https://app.xwink.fun/flair-bloom/jx3/column.json`。打开专栏时联网取一次，按「线上 → 上次取到的本地缓存 → 随包快照」的顺序回落。随包快照在构建时直接读同一个文件，只有一个数据来源。理由：白皮书每个赛季会换，宏更新更勤，随应用发版会滞后。应用不直接调 JX3Box：它的接口没有公开文档，一改格式，所有已装的客户端都会坏，修复还得等发版；由我们的站点中转，坏了只需要改脚本、重新发布站点。
- **D2 门派 → 心法两级分组**（作者选定）。门派 id 沿用主题预设的 id；打开专栏时默认选中当前主题色对应的门派。理由：同一门派不同心法的攻略和宏完全不同；沿用主题 id 不用另造一套映射，用户配色本身就暗示了在玩的门派。
- **D3 人人可用**，不是权益（作者选定）。理由：内容都是公开攻略的外链，锁起来意义不大，反而能吸引剑三玩家。
- **D4 入口放在 ☰ 菜单**，打开一个铺满面板的对话框，分「首页 / 白皮书 / 宏」三个页签（作者选定）。首页放 JX3Box 首页外链和一句说明。理由：不动现有的竖版、横版布局，标题栏按钮已经够多。
- **D5 外链只放行数据里出现过的 `https` 地址**：新命令 `open_jx3_link(url)` 校验协议为 https，且 url 在后端当前持有的专栏数据里；JX3Box 首页作为 `open_link` 的一个固定目标。理由：白皮书可能在 JX3Box 以外的网站（NGA、B 站），做域名白名单会漏；只认数据里的地址，就算前端被注入脚本，也只能打开这份列表里的链接。
- **D6 宏条目给「复制云端宏名」按钮**，复制的是 `作者#宏名`，旁边一句提示：在游戏内插件里粘贴即可同步云端宏。宏条目带 `kind`（一键宏 / 多段宏），由人工标注。理由：玩家拿名称的唯一用途就是粘贴进插件，复制比手抄可靠；格式与 JX3Box 宏页面的复制按钮一致。JX3Box 的数据里没有一键 / 多段这个字段，只能看标题和说明判断。
- **D7 只存标题、作者、链接与宏名，不搬运正文。** 理由：尊重原作者，内容以原站为准，原作者更新了这边不会过期。
- **D8 数据带 `schema` 版本号**：应用只认自己支持的版本，遇到更高版本就用缓存或快照，并提示更新应用；多出来的字段忽略。理由：站点可以先于应用发布，旧版应用不能因为格式变了而显示空白。
- **D9 列表由脚本从 JX3Box 拉候选、人工挑选后生成**：`scripts/jx3-harvest.ts` 按心法拉白皮书和宏帖，生成候选清单（含收藏、点赞等排序依据）；作者勾选后由脚本写出 `column.json`。这个脚本只在开发机上跑，不进应用。理由：四十多个心法纯手工整理太费劲，自动全收又会混进过期帖和低质量的宏；半自动的话，每个赛季更新一次也只要一小时左右。

- **D10 只收录重制版**（作者定，2026-10-29）：采集时只取 `client=std`，界面上不做客户端切换。理由：重制和缘起的技能、宏互不通用，混在一起会误导玩家。
- **D11 作者授权的条目置顶并标明**：白皮书和宏的条目可以带 `authorized: true`，在所在心法的列表里排第一，显示「作者授权推荐」标识；采集脚本回写时不覆盖这类条目。只放链接、不搬正文，和其他条目一样（作者选定）。首条：花间游《【苍生铸世】花间PVE攻略》，作者轻尘，`https://www.jx3box.com/bps/110519`，作者轻尘已授权（2026-10-29，由本项目作者转达）。理由：得到授权的内容值得被优先看到；标出来是对原作者的尊重，也能让玩家知道这条是经过确认的。

## 4. 任务卡 / Task cards

### T1 — 数据格式与校验 · 进度: 未开始

- **Change:** 定 `column.json` 的结构：`schema`、`updated_at`、`schools[{ id, name, specs[{ id, name, role }] }]`、`whitepapers[{ spec, title, author, url, authorized? }]`、`macros[{ spec, kind, name, author, url, authorized? }]`；门派 id 与 `theme.ts` 的预设 id 一致。新建 `apps/site/public/jx3/column.json`，填全部门派与重制版心法，列表里先只放 D11 的首条（花间游，轻尘，已授权）。`scripts/jx3-column.test.ts` 校验：结构正确、`spec` 都能对上、url 都是 https、门派 id 都在主题预设里、没有重复条目。
- **Acceptance:** `pnpm test:ui` 通过；故意写错一个 `spec` 或写一个 http 链接，测试会红。
- **Rollback:** 新文件，删掉即可。
- **Depends on:** 无

### T2 — 后端：拉取、回落、外链放行 · 进度: 未开始

- **Fixes:** I2
- **Change:** 新模块 `commands/jx3.rs`：`get_jx3_column(refresh)` 按 D1 的顺序取数据，返回 `{ data, source: remote | cache | bundled, fetched_at }`；线上取到且 `schema` 受支持时写进 `{app_data_dir}/jx3-column.json` 作为缓存；随包快照用 `include_str!` 读 `apps/site/public/jx3/column.json`；超时 5 秒，复用激活的 HTTP 客户端配置。`open_jx3_link(url)` 按 D5 校验后走 `shell_open`。`open_link` 加固定目标 `jx3box`。
- **Acceptance:** 断网时返回快照；线上返回更高 `schema` 时回落缓存；不在数据里的 url、http 链接都被拒绝。
- **Test:** 回落顺序、`schema` 判定、链接放行写成纯函数单测；`#[ignore]` 的线上测试打一次真实地址。
- **Rollback:** 回退提交；不打开专栏就不会调用这两个命令。
- **Depends on:** T1

### T3 — 前端：专栏对话框 · 进度: 未开始

- **Change:** ☰ 菜单加「剑网三专栏」，打开铺满面板的对话框，含三个页签。首页：JX3Box 首页外链与说明。白皮书 / 宏：上方选门派（默认当前主题对应的门派）和心法，下方列标题、作者，点击打开外链；`authorized` 的条目排在最前，带「作者授权推荐」标识（D11）；宏条目额外显示宏名、类型标签和「复制云端宏名」按钮（复制 `作者#宏名`，D6）。底部一行写数据来源与更新时间，回落到缓存或快照时说明原因。空列表显示「这个心法还没收录」。
- **Acceptance:** 竖版、横版、亮暗主题、放大和最大化下都不挤；切门派、心法、页签都不卡；复制后有提示；万花 → 花间游 的白皮书第一条是轻尘的攻略，带授权标识。
- **Test:** 门派默认选择、心法过滤、授权条目置顶、来源文案写成纯函数放进 `scripts/*.test.ts`；浏览器 mock 截图核对。
- **Rollback:** 去掉菜单项。
- **Depends on:** T2

### T4 — 采集脚本与首批内容 · 进度: 未开始

- **Change:** 按 D9 写 `scripts/jx3-harvest.ts`：读 `column.json` 里的心法表，逐个心法请求 JX3Box 的 `bps` 与 `macro` 列表（按 D10 只取 `client=std`），生成一份按心法分组的候选 Markdown 清单（标题、作者、链接、更新时间、热度），作者勾选后，脚本把勾中的条目写回 `column.json`，按 D11 跳过已授权的条目。宏帖按 `post_meta.data[]` 拆成一条宏一行，`kind` 留给人工标注。请求之间留间隔，只在开发机上手动跑。用它产出当前赛季的首批内容。
- **Acceptance:** 每个心法至少一篇白皮书，常见心法至少有一条宏；所有链接都能打开；从游戏插件里用复制出来的云端宏名能同步到。
- **Test:** 候选清单和回写的解析逻辑写成纯函数，用存进 `scripts/fixtures/jx3box/` 的真实接口响应作夹具测试；T1 的校验通过；脚本可以加 `--check-links` 逐条请求链接，确认没有 404。
- **Depends on:** T1；需要作者勾选

## 7. 风险与回滚 / Risks & rollback

- **R1 外链失效：** 原作者删帖、改链接。T4 脚本的 `--check-links` 可以随时重跑；以后要不要做定期巡检，按失效频率再定。
- **R4 JX3Box 接口改版：** 只影响采集脚本，不影响已装的应用（D1）；改版后修脚本即可。采集时请求量很小（每个心法两次请求），也不碰需要登录的接口。
- **R2 产品站被篡改：** 最多能让专栏显示错误的列表，并打开列表里的 https 链接；不能执行本地操作。现阶段不做签名，站点出过安全事故再考虑。
- **R3 版权与署名争议：** 只放标题、作者和原文链接（D7）；原作者要求下架时，删掉条目并发布一次站点即可。
- **回滚：** 删掉菜单项即可隐藏整个专栏；站点上的 json 留着无害。

## 8. 范围外 / Out of scope · follow-ups

- 把剑三游戏宏直接转换成本应用的连发规则（多段宏 → 互斥组）：两边的语义差别很大，等有人提再单独评估。
- 专栏内搜索、收藏、按赛季切换。
- 应用直接从 JX3Box 拉数据：等对方有公开、稳定的接口再说。
- 按热度自动排序（JX3Box 的 `/api/macro/tops` 有按心法的 7 天热度，但所在的服务域名还没确认）。
