# 剑网三专栏 — 改造路线图 / Change Roadmap

Status: active（进行中）
Goal: ☰ 菜单打开「剑网三专栏」，按门派、心法找到白皮书和一键宏 / 多段宏，一点直达原文，宏名一键复制后可在游戏里的插件中同步；列表随赛季更新时不用发应用新版本。

---

## 1. 背景 / Background

应用的玩家主要是剑三玩家，面板本就有 20 套门派配色（`panel/theme.ts:39-58`，id 即门派拼音）。玩家配连发之前通常要先查心法白皮书和宏，现在只能自己去 JX3Box 翻。

| 能力 | 现状 |
| --- | --- |
| 打开外部链接 | 有 `open_link`，但只认写死的几个名字（`commands/app.rs:27`），刻意不给 WebView 开「打开任意网址」的口子 |
| 联网取数据 | 有：激活兑换码用的 `reqwest` 客户端（`commands/license.rs:402`） |
| 托管静态文件 | 有：产品站 `apps/site`（Nuxt，`baseURL = /flair-bloom/`），`public/` 下的文件原样发布；推 `site-v*` tag 发布，不经 updater |
| 门派列表 | 有：主题预设的 20 个门派 id 与中文名 |
| 心法列表、白皮书、宏数据 | 无 |
| JX3Box 数据接口 | 有，但没有公开文档（2026-10-29 实测）：`https://cms.jx3box.com/api/cms/posts?type=bps&subtype=<心法>` 是职业攻略，`type=macro` 是宏帖，`post_subtype` 是心法名，`client` 区分重制（`std`）与缘起；一篇宏帖的 `post_meta.data[]` 里有多条宏，各带 `name`、宏文本、按键速度建议。游戏插件同步用的云端宏名是 `作者#宏名`（宏页面的复制按钮就是这样拼的） |

不可破坏的不变量：

- 联网只读取、不上传；取不到不影响启动和连发。
- WebView 仍然不能打开任意网址：外链只放行当前加载的专栏数据里出现过的 `https` 地址。
- 断网、产品站挂掉时，专栏照样能打开，显示内置快照。

## 2. 决策 / Decisions

- **D1 数据由产品站托管，应用内置一份快照**（作者选定）。列表文件放在 `apps/site/public/jx3/column.json`，发布后的地址是 `https://app.xwink.fun/flair-bloom/jx3/column.json`。启动时在后台取一次（D13），按「线上 → 上次取到的本地缓存 → 随包快照」的顺序回落。随包快照在构建时直接读同一个文件，只有一个数据来源。理由：白皮书每个赛季会换，宏更新更勤，随应用发版会滞后。应用不直接调 JX3Box：它的接口没有公开文档，一改格式，所有已装的客户端都会坏，修复还得等发版；由我们的站点中转，坏了只需要改脚本、重新发布站点。
- **D2 门派 → 心法两级分组**（作者选定）。门派 id 沿用主题预设的 id；打开专栏时默认选中当前主题色对应的门派。理由：同一门派不同心法的攻略和宏完全不同；沿用主题 id 不用另造一套映射，用户配色本身就暗示了在玩的门派。
  - 第一级除了门派还有**流派**：`schools[].kind` 取 `sect`（门派）或 `genre`（流派）。目前的流派只有无相楼（幽罗引）：它不属于任何门派，所有玩家都能选作第二心法（作者说明，2026-10-29）。选择器里流派单独成组，排在门派后面。无相楼也有一套主题色「丁香」（取 JX3Box 的门派色 `#a18de3`），用这套配色打开专栏时默认选中无相楼。
  - 心法表取自 JX3Box 的公开数据包 `@jx3box/jx3box-data`（MIT）里的 `xf.json` 与 `mount_group.json`（外攻、内攻算输出，另有坦克、治疗），只保留重制版有的心法。藏剑在 JX3Box 上只用「问水诀」一个心法名（「山居剑意」下没有帖子），收一个心法。
- **D3 人人可用**，不是权益（作者选定）。理由：内容都是公开攻略的外链，锁起来意义不大，反而能吸引剑三玩家。
- **D4 入口放在 ☰ 菜单**，打开一个铺满面板的对话框，单页两段（作者选定）：标题栏右侧放 JX3Box 首页外链；标题下一行选门派（下拉出色块网格）和心法（分段器，与下拉同高同圆角，按 `@xwink/ui` 工具组配方）；正文上段白皮书、下段宏。理由：不动现有的竖版、横版布局，标题栏按钮已经够多；选一次心法两段同时看，比来回切页签省事。
- **D5 外链只放行数据里出现过的 `https` 地址**：新命令 `open_jx3_link(url)` 校验协议为 https，且 url 在后端当前持有的专栏数据里；JX3Box 首页作为 `open_link` 的一个固定目标。理由：白皮书可能在 JX3Box 以外的网站（NGA、B 站），做域名白名单会漏；只认数据里的地址，就算前端被注入脚本，也只能打开这份列表里的链接。
- **D6 宏按帖子收录，帖子里每个宏一个复制按钮**：作者常把起手、循环、爆发几个宏放在同一篇帖子里（JX3Box 的 `post_meta.data[]`），所以 `macros[]` 一条是一篇帖子，`items[]` 是帖子里的各个宏；按钮复制 `作者#宏名`，悬停提示在游戏内插件里粘贴即可同步云端宏。白皮书里直接贴出的宏没有云端宏可同步，作为一条 `macros[]` 收录（链接指向白皮书），每个宏带 `body` 正文，界面显示正文，按钮复制正文、粘贴进游戏的宏编辑。帖子带 `kind`（一键宏 / 多段宏），由人工标注。校验拦下同一作者两篇帖子里撞名的宏。理由：玩家拿宏名的唯一用途就是粘贴进插件，复制比手抄可靠；格式与 JX3Box 宏页面的「复制云端宏」一致（作者核对，2026-10-29：`蔓海赋尘#太极秘录循环宏`、`蔓海赋尘#起手宏太极秘录`）。JX3Box 的数据里没有一键 / 多段这个字段，只能看标题和说明判断。
- **D7 只存标题、作者、链接与宏名，不搬运正文；唯一例外是作者授权条目里的宏正文**（作者定，2026-10-29）。校验拦下没授权却带 `body` 的条目。理由：尊重原作者，内容以原站为准，原作者更新了这边不会过期；宏正文短、玩家要的就是它，白皮书里的宏又没有云端宏名可复制，有授权才收。代价是作者改了宏这边要跟着改，`authorized_note` 写明宏摘自哪里。首例：轻尘白皮书里的循环宏与两档爆发宏。
- **D8 数据带 `schema` 版本号**：应用只认自己支持的版本，遇到更高版本就用缓存或快照，并提示更新应用；多出来的字段忽略。理由：站点可以先于应用发布，旧版应用不能因为格式变了而显示空白。
- **D9 采集到的数据存在仓库里，不发布**：`scripts/jx3-harvest.ts` 按心法从 JX3Box 拉白皮书和宏帖，写进 `scripts/jx3/candidates.json`（标题、作者、链接、更新时间、热度）。这个文件不在 `public/` 下，不随站点发布，也不进应用；它是邀请作者授权时的名单，也是 D11 折叠区公开帖的来源。脚本只在开发机上手动跑。理由：数据拿到就存，事后再找成本更高；全量候选只用来邀请，对外只露 D11 限定的那几条。
- **D10 只收录重制版**（作者定，2026-10-29）：采集时只取 `client=std`，界面上不做客户端切换。理由：重制和缘起的技能、宏互不通用，混在一起会误导玩家。
- **D11 授权的常驻，没授权的公开帖折叠**（作者定，2026-10-29）：条目的 `authorized_at`（授权日期）与 `authorized_note`（谁授权、怎么转达的）要么都写、要么都不写，校验拦下只写一半的。带授权的常驻展示，标「✓ 作者授权」；不带的是公开帖，每个心法最多 3 篇白皮书、5 篇宏帖，默认折叠在「公开收录的热门 · N 条」里，展开后每条标「来源 JX3Box」等站名，并写明作者不希望收录的联系即下架。面向用户的文字只说「公开收录的热门」，不写「未授权」「未经作者确认」（作者定，2026-10-29）。只放链接、不搬正文。首条授权：花间游《【苍生铸世】花间PVE攻略》，作者轻尘，`https://www.jx3box.com/bps/110519`，2026-10-29 授权，由本项目作者转达；文中的宏一并收录（D7）。理由：只放标题和链接一般不构成转载，但成批搬运他人的列表有不正当竞争的风险，链到侵权内容也有连带风险；只露少量、写明来源、给下架通道，同时把授权内容放在显眼处，既让空心法有东西可看，也让作者看得到授权的好处。授权记录写进数据，以后有争议能查到来源。
  - 既然叫「热门」，公开帖必须按热度挑。JX3Box 的列表接口不带热度，也不认 `order` 参数（带了返回 502），所以 T4 要接热度接口：宏用 `/api/macro/tops`（按心法的 7 天热度），白皮书找到对应接口前人工挑。首版折叠区只有作者手选的一篇（蔓海赋尘的花间一键宏）。
- **D12 公告和专栏里都明确邀请攻略作者授权**（作者定，2026-10-29）：专栏首页放一段邀请，说明收录方式（只放标题、作者和原文链接，不转载正文）和联系方式；某个心法还没有授权内容时，列表空状态就显示这段邀请，而不是「还没收录」；更新公告的「新功能」里也写上。联系方式先用现有的「支持&帮助」（产品页支持一节）。理由：首版大部分心法是空的，空状态本身就是招募入口。
- **D13 联网说明只写一句「启动时从官网拉取必要信息」，兑换码单列**（作者定，2026-10-29）：README 与产品页不再逐项列检查更新、专栏；激活兑换码照旧单独写明会提交数据。为了让这句话属实，专栏数据改为启动时在后台预取（`jx3::prefetch`），打开专栏直接用；「刷新」按钮再取一次。理由：逐项列举每加一处联网就要改一次承诺；兑换码会发送数据，性质不同，必须单独写。

## 7. 风险与回滚 / Risks & rollback

- **R1 外链失效：** 原作者删帖、改链接。T4 脚本的 `--check-links` 可以随时重跑；以后要不要做定期巡检，按失效频率再定。
- **R4 JX3Box 接口改版：** 只影响采集脚本，不影响已装的应用（D1）；改版后修脚本即可。采集时请求量很小（每个心法两次请求），也不碰需要登录的接口。
- **R2 产品站被篡改：** 最多能让专栏显示错误的列表，并打开列表里的 https 链接；不能执行本地操作。现阶段不做签名，站点出过安全事故再考虑。
- **R3 版权与署名争议：** 只放标题、作者和原文链接（D7）；原作者要求下架时，删掉条目并发布一次站点即可。
- **回滚：** 删掉菜单项即可隐藏整个专栏；站点上的 json 留着无害。
