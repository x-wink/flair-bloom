# 面板等比缩放与主题对比度 — 改造路线图 / Change Roadmap

Status: active（T1–T3 完成；T4、T5 进行中，完成后随下一版发布）
Goal: 大屏用户能把面板（及浮窗）等比放大，也能一键最大化；所有主题色在明暗两档下文字都过 WCAG AA 4.5:1。

---

## 1. 背景 / Background

亲友反馈：大屏上面板太小；粉色主题下灰色提示字看不清。实测灰字 #888 叠在主色渐变底上只有 2.3–2.8:1，20 个预设全部不达标；白字实底在绯粉、流金等 9 个亮色上也不过线。

## 2. 决策 / Decisions

- D1 对比度按 xwink-ui 规范：文字四档在三种 surface 与叠满淡染的面板底上都过 4.5:1，严格单调；面板主色淡染压到 `APP_TINT_MAX = 0.15`（作者选「背景减淡 + 文字换档」）。
- D2 实底前景按对比度取白或近黑，主色不改（作者选「主色不变，亮主色改用深字」）。
- D3 颜色算法在仓内 `contrast.ts` 移植 `@xwink/ui/brand`，不直接依赖：发版工作流无私有源凭据，Node 测试不剥离 node_modules 的 TS。界面迁到 Vue（vue-migration）后换回包里的实现。产品页已直接用包里的 `brandVariables`。
- D4 窗口拖边缩放，设计尺寸即最小尺寸，比例在拖动中由系统锁住：Windows 拦 `WM_SIZING`，macOS 设 NSWindow `contentAspectRatio`。不用「静止 400 ms 再吸附」——作者试用后嫌手感怪。
- D7 拖边以拖动开始时的窗口中心为准向四周缩放，碰到屏幕边缘时窗口整体往回推，始终留在当前屏幕的工作区里（作者选「不出屏优先」）。只管缩放，拖标题栏移动窗口不拦。理由：从中心放大比单向撑开更像在放大内容；如果中心绝对不动，放在角落的窗口几乎放不大。
- D8 最大化 = 当前屏幕工作区装得下的最大等比尺寸、居中，取消最大化回到之前的位置和大小。模拟系统行为：标题栏按钮、双击标题栏切换；最大化时不能拖边；最大化后拖标题栏即还原并跟着鼠标走；记住最大化状态，重开面板仍是最大化。理由：比例锁着，铺满整个工作区会变形，只能取等比最大。
- D9 最大化期间不改各布局记住的缩放比例，浮窗也不跟着放大。理由：取消最大化要回到原来的大小；浮窗只有一行胶囊，放大到最大没有意义。
- D5 设计尺寸取常用比例：竖版 405×720（9:16），横版 1072×603（16:9，排版至少需要 1060×580，只往大取）。
- D6 竖版、横版各记一个比例，上限各按自己的设计尺寸卡当前屏幕工作区；浮窗不拖边，跟随面板当前布局的比例。

## 3. 任务卡 / Task cards

### T1 — 主题对比度 · 进度: 已完成（2026-10-29）

`theme.css` / `theme.ts` / `contrast.ts`，主色文字 `--fb-color-primary-text`、语义色文字 `--fb-color-*-text`，`scripts/theme-contrast.test.ts` 钉住 20 预设 × 明暗。浏览器 mock 截图核对过绯粉亮色、流金暗色、设置页。

### T2 — 面板与浮窗等比缩放 · 进度: 代码完成，待 Windows 真机验收

`windowScale.ts` / `useWindowScale.ts` / `commands/window.rs`（`lock_aspect` 单测）/ 浮窗跟随；设置 → 通用 → 外观显示缩放并可复位。Windows 侧 subclass 只在临时 crate 里对 Windows 目标做过类型检查与 clippy，完整交叉编译在 mac 上跑不了（ring 缺 MSVC 头文件）。

### T3 — Windows 真机验收 · 进度: 已完成（2026-10-29，作者实测）

拖四边四角锁比例、最小尺寸与工作区边缘、高 DPI 与跨屏、放大后走线与引导气泡、浮窗跟随、横版排版全部通过。

### T4 — 拖边以中心为准缩放、不出屏 · 进度: 代码完成，待 Windows 真机验收

- **Change:** `commands/window.rs`：`WM_ENTERSIZEMOVE` 记下窗口中心与所在屏幕的工作区，`WM_EXITSIZEMOVE` 清掉；`WM_SIZING` 改为按被拖的边到中心的距离算尺寸（拖左右边看宽，拖上下边看高，拖角取较大的那个），以中心为准摆放，再整体推回工作区。换算仍是纯函数，替换 `lock_aspect`。
- **Acceptance:** 拖任意边或角，窗口以中心为准向四周放大缩小，比例不变；靠近屏幕边缘放大时窗口被推回、不出屏，最大仍能放到工作区装得下的等比尺寸。
- **Test:** `window_tests.rs` 覆盖四边、四角、最小与最大尺寸、贴左上和右下边推回；Windows 真机拖一遍。
- **Rollback:** 回退提交即恢复「对边不动」。

### T5 — 最大化 / 取消最大化 · 进度: 未开始

- **Change:** 前端 `windowScale.ts` 加最大化矩形的纯计算，`useWindowScale.ts` 管最大化状态（存 settings，还原用的位置大小只在本次运行内记）：最大化时 `setResizable(false)`，期间 resize 事件不写缩放比例、不广播给浮窗（D9）。标题栏在最小化按钮前加最大化 / 还原按钮；标题栏改为自己处理按下：双击切换，最大化状态下按住拖动先还原（鼠标在标题栏上的横向比例不变）再 `startDragging`。切换布局时保持最大化；设置里点「复位缩放」先取消最大化。
- **Acceptance:** 按钮、双击都能切换；最大化后不能拖边；最大化后拖标题栏，窗口还原并跟着鼠标走；关掉面板（或切到浮窗）再打开仍是最大化；取消最大化回到原位置和大小；浮窗大小不受影响。
- **Test:** `scripts/*.test.ts` 补最大化矩形与还原位置的纯函数测试；Windows 真机走一遍上面各条。
- **Rollback:** 回退提交；settings 里多出的最大化状态旧代码会忽略。
