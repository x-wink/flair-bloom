# 启动行为与分发链路 — 路线图

Status: completed
Goal: 五件用户能直接感知的小事：更新与下载全部走 gh-proxy 加速、GitHub 直连兜底，自家服务器退出安装包分发；启动即可自动开连发；可以让应用自己提权启动；任何最小化路径都收进浮窗而不是只剩托盘图标。

---

## 1. 背景

README「接下来」攒了五条与启动、分发有关的小需求，实现面互不重叠，一批做完：

| #   | 需求                                             | 现状                                                                       |
| --- | ------------------------------------------------ | -------------------------------------------------------------------------- |
| R1  | 更新器优先走加速通道，GitHub 兜底                | `build_updater` 给唯一端点无条件套代理前缀，代理挂了没有退路               |
| R2  | 产品页下载不再经自家服务器中转                   | 下载链接指向 app.xwink.fun 镜像，安装包流量全在自家带宽上                   |
| R3  | 启动后自动打开全局开关                           | 无此设置，每次启动都要手动开                                               |
| R4  | 「以管理员模式启动」开关                         | 只有「提权重启」按钮，每次进游戏模式都要点一次                             |
| R5  | 最小化固定收进浮窗                               | 标题栏最小化按钮已收浮窗，但系统级最小化（Win+D / 任务栏 / Aero Shake）走原生最小化 |

## 2. 决策

- **D1：撤掉服务器发布镜像，清单与安装包都走 `gh-proxy.com`。** 更新器端点改为「代理版 latest.json → GitHub 原始 latest.json」两条，按序兜底；下载地址同样代理优先、失败回退原始地址。自家服务器只留静态产品页，不再同步、不再托管安装包。代价很小：镜像同步本身就走 gh-proxy、失败才回落直连（国内约 20 KB/s），代理挂掉时镜像也拿不到新版本，撤不撤都是同一个单点依赖；真正失去的只有「已同步落盘的旧版本在代理不可用时仍能下载」。换来零带宽成本与零同步基础设施。哪天要回来，镜像那套按 git 历史恢复即可。
- **D2：产品页版本数据在浏览器里直读 GitHub API（经 gh-proxy）。** 不烤进静态站，发版后产品页自动跟上，不用重发站点——与原镜像清单同一目的。读不到时退到「前往 GitHub 发布页」。
- **D3：「以管理员模式启动」用注册表兼容性标志**，向 `HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers` 写入 exe 路径 → `~ RUNASADMIN`。普通权限即可写、开关即时生效、关掉就删值。⚖️ 代价：每次启动仍弹一次 UAC（免 UAC 要计划任务 + 一次管理员授权，且更新换路径后任务失效），先要简单可靠的那档。
- **D4：三个启动相关开关两两互斥，开一个自动关另一个并 toast 说明。** 「开机自启」×「启动后自动开全局」——防止开机就在后台连发；「开机自启」×「以管理员模式启动」——`HKCU\Run` 拉起需要提权的程序会被系统静默拦下，开机根本起不来，比互斥更难排查。
- **D5：系统级最小化在 Rust 侧接管。** `on_window_event` 收到面板最小化就 `unminimize` 再 `enter_float_mode`，浮窗缺失时保留面板（沿用现有兜底）。关闭行为的三档设置与询问框保持原样，本次不动。

## 4. 交接

- **服务器侧需人工收尾**（CI 不下发 systemd 与 nginx 片段）：停并禁用 `flair-bloom-mirror.timer`、`flair-bloom-mirror.service`，删 `/opt/flair-bloom/mirror` 与 `/opt/flair-bloom/mirror-app`，下发新的 `flair-bloom.conf` 后 `nginx -t` 再 reload。撤掉路由前先确认没有老版本客户端还在读 `/flair-bloom/releases/latest.json`——0.3.1 及更早的更新器端点指向 GitHub，不经镜像，可以直接撤。
- 本批改动跨应用与产品页两条发布链：应用走 `v*` tag，产品页走 `site-v*` tag，互不依赖，可分别发。
