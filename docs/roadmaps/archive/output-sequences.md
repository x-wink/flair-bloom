# 统一输出队列与录制 — 改造路线图

Status: archived（0.9.0 已发布；DD／外设等剩余真机验收保留为后续项）
Goal: 每条规则用同一份“按键＋间隔”步骤队列输出，支持奶药“四白一赤、当归赤”等固定技能顺序；长度为一的队列覆盖现有单键连发，长按／切换继续决定何时运行。

界面决策以 [连发序列编辑界面精简](sequence-editor-simplification.md) 为准：序列编辑收进高级设置，复用规则自动保存，前端不提供试播或显式保存。本文涉及草稿、试播与一次保存的验收记录不作为当前界面要求；后端队列与停止安全契约仍适用。

## 1. 成功标准与现状

- 旧单键配置转换为一步队列，按键、间隔、触发、独立停止键、启用状态与分组完整保留。
- 用户能手动编辑多步队列；长按时循环、松手停止，切换时按一次循环、再按停止。运行时按顺序点按各步，末步间隔结束后回到首步。
- 录制与手动编辑生成同一种步骤数据，使用同一个播放器；录制后能预览、修正并保存。
- 任意等待、按下或恢复阶段都能急停；切配置、切后端、退出和异常清理没有残留按键或旧队列复活。
- 使用合成队列验收发送顺序、最短间隔、循环、暂停与停止，不依赖游戏循环或技能施放成功。

| 能力 | 已验证现状 | 本次缺口 |
| --- | --- | --- |
| 规则契约 | `BurstRule` 含单个 `target_key`、规则级 `interval_ms`，`BurstMode` 只有 Hold／Toggle | 将输出统一成非空步骤列表，迁移所有读写方 |
| 调度与停止 | 单调度线程、Down／Up 相位、generation、按键所有者表、成功注入账本 | 步骤游标、跨步计时、暂停快照、完成／失败通知 |
| 分组 | 长按插队暂停，松手恢复切换规则；恢复调用 `start_rule` | 暂停目前会销毁调度状态，无法保留步骤位置 |
| 配置 | `.qzh` 加密、迁移、原子写入、导入导出与装载净化 | 队列兼容协议；旧版启动加载失败会写默认配置，单纯拒读不足以防丢失 |
| 录入与录制 | 前端 `KeyCapture` 捕获一次按键；后端有物理键监听与去重 | 全局、有界的录制会话及按键时间到步骤的转换 |
| 序列定义 | `macro_seq.rs` 只有裸 VK＋Press／Release＋延时的数据类型，无运行调用方 | 不能当现成宏引擎复用；避免再落一套独立宏格式 |
| 界面 | 竖版规则卡、横版单键编辑、浮窗与运行／暂停状态 | 步骤编辑、进度、录制预览；横版防止覆盖多步规则 |
| 测试 | 调度器虚拟时钟、dispatcher 替身、引擎命令录制替身 | 顺序、暂停、失败、兼容和录制状态机用例 |

公开参照：[Logitech 宏手册](https://www.logitech.com/assets/51813/26/lgs-guide.pdf)将按键序列、延时与重复方式分别配置，[编辑说明](https://support.logi.com/hc/en-us/articles/360023235914-Adding-mouse-clicks-and-timing-delays-to-macros)支持修改录制结果。这里采用序列与触发分离的做法，按本项目已定方向进一步将单键统一为一步队列。

## 2. 已定决策

- **D1 只有长按／切换两种触发模式。** 用户明确确定；队列不增加第三种触发模式。
- **D2 所有输出都是队列，单键是一步队列。** 用户明确确定；领域模型、IPC 与运行时共用 `steps`，每步为按键与间隔，不另设 single／sequence 目标类型或两条播放器路径。
- **D3 序列属于规则。** 触发、停止键、分组与启用状态仍放在规则上，输出步骤放在规则内；奶药循环是这份通用契约的实际消费者。
- **D4 实施独立队列与录制。** 已获用户开工授权；不创建发布版本或触发发布。
- **D5 独立实施队列与录制。** 用户明确要求不合并组合键，并已授权开工；每步使用现有单个 KeyId，不扩展修饰键调度，也不以组合键任务作为前置条件。
- **D6 配置目录隔离。** 新版使用独立目录与激活记录并保留旧目录；schema 5 配套完整 v4→v5 迁移，旧单键转换为一步队列，新文件没有旧目标字段。T1／T2 验证旧读取器拒读导出文件及目录隔离，避免旧版启动回退触及新版配置。

- **D7 验收与游戏无关。** 用户明确要求编造目标队列；采用 E→E→R 等合成步骤，不索取奶药键位或节奏作为前置。
- **D8 队列负责严格顺序和最早时间。** 用户要求调度器只消费队列到期动作；从成功发送完成后等待完整间隔，截止前不输出。迟到只记录提示，继续按序跑完整轮，不停止、不跳步、不追赶；用户主动停止和急停仍即时生效。

### 实施采用的取值

用户已授权按独立队列规划开工，以下为实现取值与对应测试范围。

| # | 决策点 | 建议默认值与原因 | 影响 |
| --- | --- | --- | --- |
| P1 | 间隔、范围与点按时长 | 间隔指本步 down 到下步 down 的最短时间，含点按时长；末步同理。首版沿用有效 10～10000ms、每规则 1～256 步，点按时长沿用现有派生逻辑；不增加独立按住时长字段 | T2、T3；更长等待或长按输出需扩范围 |
| P2 | 正常停止与临时暂停 | 松手／切换停止清进度，下次从首步开始；同组插队冻结进度和剩余等待，恢复不重发已成功 down 的步骤。等待时间在暂停期间不流逝 | T3、T4；影响一步规则插队恢复的起拍时机，需一起验收 |
| P3 | 同目标并发与迟到 | 每个步骤应有完整点按，不沿用“共享同一 down 就算执行”的合并方式；同键占用时公平延后，过载只拉长、不跳步、不连发追赶 | T3；一步规则共享目标的合并行为会变化，需明确验证实际总速率 |
| P4 | 首版录制范围 | 先做普通键盘键的顺序点按录制，生成按键＋间隔；忽略系统自动重复，保留真实重复点按。长按时长、重叠按键、修饰组合与鼠标操作不承诺原样重放，界面明确说明并标出不支持片段 | T6；完整键鼠事件录制会显著扩大格式与调度范围 |
| P5 | 交付顺序 | 先交付手动队列和完整停止能力，再接录制到同一编辑器；两阶段都是这份规划的范围 | 可先验证实际循环节奏，再投入录制 |

配置持久化采用 D6，旧文件经完整临时文件复制后才出现正式文件，v4→v5 迁移保留全部规则控制字段。硬条件是：旧版不得把多步队列执行成单键，新版写入前保留可恢复的旧配置，旧版的启动兜底与保存操作不能让唯一副本不可恢复。不预先把裸升 schema、缺必填字段或 `enabled=false` 投影认作已解决兼容。

## 3. 建议设计

### 3.1 一份规则契约

```text
规则
├─ id、enabled、group
├─ mode：hold / toggle
├─ trigger_key、stop_key
└─ steps：非空、有序
   ├─ key：现有 KeyId
   └─ interval_ms：到下一个步骤按下的间隔
```

- 正规化后的规则没有独立 `target_key` 和规则级输出间隔；旧字段只可存在于兼容读取／写入适配层，不能作为另一份可独立修改的事实。
- 旧配置正规化为一个步骤；默认规则、新建规则、第三方导入、示例教程规则都走同一构造入口。
- 步骤数与间隔检查归结构校验；按键能力、触发／停止重合关系归 `key_policy`，装载仍必经统一净化入口。不支持某步时禁用并说明整条规则，不静默删步或重排。
- 空队列不能保存；编辑器保留最后一步或把空列表视为未提交草稿。总步骤数与周期累计使用检查过的算术，边界在 IPC、导入和文件加载一致生效。
- 首版不加入嵌套循环、条件分支、按成功推进、随机抖动或技能专用逻辑。相同按键可出现多次，执行顺序严格按下标。
- 当前未使用的 `MacroSequence`／Press／Release 模型在调用方核查后移除或收敛到本契约，不发布独立宏文件／独立播放器。

### 3.2 调度、暂停与失败

- `OutputQueue` 封装步骤游标、按下／释放相位、最早时间、循环、暂停和迟到记录；调度器只取到期的 `QueueAction`、协调通道与节流、回报完成时间。独立运行标识隔离旧回报。
- 首步立即可调度；成功发送完成的完整 `Instant` 是后续计时基点，不截断到毫秒，也不沿用迟到前的旧时刻。先完成释放再执行下一步，同键保留 up→down 边界；间隔包含按压，不额外叠加规则级延时。
- 复用现有总速率限制与实际事件成本核算，长等待规则不持续占用输出键。选择到期步骤使用稳定、公平顺序，不能靠 HashMap 遍历决定冲突顺序。记录最近／最大延后时间，任意迟到都不自动停止、跳步或追赶，顺序与最短间隔优先于绝对时刻。
- 暂停在当前 down 已成功时先释放该键，将该点按视为已发生，冻结到下一步的剩余等待；down 尚未发送则保留当前步。恢复后不重复已发送点按。跨线程暂停／恢复必须串行且带运行标识，不能依赖 UI 轮询回传游标。
- 发送接口报告失败时停止该规则并清理已按下成员，回报失败位置；禁止无提示推进或自动重试技能，因为无法知道游戏实际收到多少次。接口报告成功仍只代表输入通道发送成功。
- 运行状态由后端提供步骤位置、循环计数、暂停／失败原因；面板与浮窗继续使用规则启停集合做播报，步骤切换不反复播“开始／结束”。

| 事件 | 建议处理 |
| --- | --- |
| 长按松手、切换停止、独立停止键 | 立即终止并清进度，下次首步开始 |
| 同组长按插队 | 释放当前按键、保留暂停快照；组内嵌套与栈中间松手仍遵守现有优先级 |
| 暂停期间停止／替换该规则 | 丢弃快照，之后松手不恢复它 |
| 全局关闭、改规则、换配置、切后端、退出 | 作废所有相关快照，清理按键；全局重新开启不自行恢复旧队列 |
| 单次试播 | 临时运行一次队列，复用播放器；完成、取消和失败都回收运行状态，不新增触发模式 |
| 滚轮触发 Hold | 一步队列保持现有“一格点按一次”；首版建议拒绝滚轮 Hold 绑定多步队列，避免一次滚动启动不可控数量的长序列 |

### 安全边界修复方案与验收

| 边界 | 实现约束 | 自动化证据 |
| --- | --- | --- |
| 旧规则快照跨越配置／后端切换 | 事件入口捕获代际，runtime 锁内统一校验；旧释放也不能停止复用 ID 的新规则 | `burst-engine/src/safety_tests.rs` 栅栏控制真实输入入口交错 |
| 停止后自动重复重启 | 普通停止保留物理按下态，真实 up 后才接受新 down | 长按触发与共用开关录制急停回归 |
| 急停释放失败丢账本 | 只有成功 up 清记录；正常 worker 每 50ms 重试孤立按键，ACK 返回实际清理结果，兜底失败仍保留记录 | `scheduler/safety_tests.rs` 持续失败、通道恢复、空闲重试、兜底与新 down 串行 |
| 未释放的同键再次输出 | 所有者和残留账本共同阻挡新 down；修复释放后继续原步骤，其他键正常运行 | 同键队列不推进、恢复后继续、不产生重复 down |
| 录制期间在途滚轮输出 | 滚轮与普通启动在相同 runtime 临界区检查代际、录制与输入模式切换状态 | 录制起点跨越滚轮触发的确定性交错回归 |
| 调度线程异常假运行 | 持久故障状态、进度失败、关闭开关、清活跃集合；面板／浮窗提示重启，拒绝启动／试播／录制 | 真实 worker panic、命令通道关闭、引擎状态与前端显示检查 |

所有并发停止收尾前保持 Stopping；重新启用不能让旧清理与新输出交错。切后端、试播和录制必须收到旧输出停止及释放成功的确认，失败时保留旧通道并返回错误，卸载／修复驱动也中止。正常迟到仍只顺延，以上安全边界不改变严格间隔与按序执行要求。物理输入来源过滤保持现有边界，不以这些回归替代 Windows 驱动实测。

### 3.3 编辑、横版与录制

- 一步队列保留现有简洁录键与间隔体验，点“添加步骤”直接扩展；多步显示编号、按键和间隔，支持添加、删除、复制、调序及总周期预估。
- 多步规则明确显示启动键，不再用第一个输出键代替触发。编辑在本地草稿中完成，保存前统一校验、一次提交；取消不改运行中的规则。保存变更会停止旧运行，不自动恢复旧游标。
- 横版快速三态编辑与统一间隔只作用于可完整表达的一步规则。多步规则视为高级规则，横版提供回竖版详细编辑入口；不要求横版展示其步骤与运行／暂停状态，快捷点击不得覆盖或删除它。
- 冲突检测、占用键收集、走线、浮窗、声音标签、导入预览和复制规则都遍历全部步骤；走线按输出键去重，保留队列顺序供详情展示。
- 录制会话在后端，AppHandle 留在 commands 层。开始前停止现有运行并禁止录制期间启动规则，全局紧急停止仍可用；录制结束后不自动恢复此前连发。
- 仅记录会话内经过来源过滤的物理事件；普通键按下时间决定相邻步骤间隔，重复 down 不生成新步骤。键盘钩子与面板中继须避免双录，钩子线程只做有界收集、不等前端或磁盘。
- 建议录制上限 5 分钟／256 步；取消、超限、窗口关闭、切配置／后端、全局停止和退出都有明确结束状态。未成对释放、重叠按键及不合法间隔必须标出，不能直接保存为可播放队列。
- 第一录入键之前的等待不进入循环；最后一步到下一轮的间隔使用统一连发默认值 10ms，采用后可在步骤列表中修改，不能把点击“结束录制”的耗时当作周期尾间隔。长按时长不进入首版输出数据，录制结果按点按播放。
- 带图标的「录制宏」与添加步骤并排；全局开启时先确认结束运行，再录制，无倒计时。录制预览和结束按钮置于阻止背景操作的顶层浮层，F12 提示保持按钮等高；结束后左侧重录、右侧采用，关闭即停止并放弃，未采用不替换规则。
- 录制结果先进入编辑草稿，只有用户保存才替换规则；单次试播也走同一个规则校验与播放器。

### 3.4 与其他路线图衔接

- [组合键](../key-chords.md)：保持独立草案，本期没有对它的实现依赖，不预建组合绑定类型或扩展修饰键释放逻辑。将来实施时再消费队列契约。
- [窗口绑定](../window-binding.md)：该功能尚未落地。本期为暂停命令保留原因与快照语义，不实现前台检测；它落地时需确定长时间离开游戏后继续原步还是重置，并复用同一暂停／停止契约。
- [Vue 迁移](../vue-migration.md)：按现有 React 实现估算，领域类型、录制转换与调度逻辑不依赖前端框架，不在本期迁移界面框架。

## 8. 风险、回滚与范围外

- **技能状态不可见。** 队列仅保证输入顺序，不能识别读条被打断、冷却、目标、资源与实际成功次数。首版提供停止后重置、进度可见与间隔调整，自动纠偏另行评估。
- **存量配置优先。** T1 是允许写新格式的前置条件；上线前必须在隔离目录验证已发布旧版的读取／启动／保存。新增默认字段不自动等于可安全回退；全量新格式写入前备份，保留原文件定位与恢复方法。
- **来源过滤有边界。** DD／外设依赖现有过滤机制，录制与同键触发都须实测；调度器成功回报不能证明物理来源识别正确。
- **暂停属于新能力。** 一步与多步共用冻结进度语义，需要回归一步插队手感；未来窗口绑定是否长时间保留队列进度单独确认，不在本期暗中实现。
- **范围外：** 任意 down／up 事件脚本、独立长按输出时长、键盘和鼠标重叠录制、组合键实现、坐标／轨迹、条件分支、每按一下推进一步、技能成功识别、随机抖动、内置奶药模板和新增权益体系。
